Sentinel Edge для Windows 10/11 (64-bit)
Версия 0.2.0

Что это
  Программа на компьютере в той же локальной сети, что регистратор.
  Она читает уже известные RTSP-адреса, считает людей и шлёт на сервер
  только JSON. Видео на сервер не передаётся. Лица не распознаются.
  Модель роутера не нужна и сеть не сканируется.
  Карточка LIVE и receiving_frames на сервере кадром агента не являются:
  это кадр, который открыл сам сервер.

Проверка кадра сегодня — без службы и без администратора
  Это единственный запуск для проверки салона. Install.bat для неё не нужен.
  Компьютер должен уже видеть регистратор по тем RTSP, которые салон
  использует. Файл config.env создайте сами из env.example, не в общем
  архиве и не присылайте его. Впишите адрес сервера, ключ и те же RTSP.

  В обычном окне, без «Запуск от имени администратора»:
    Run-Foreground.bat C:\path\to\config.env

  Нужен уже установленный Python 3.11+ (команда py -3). Окно не скачивает
  Python и не запускает чужой .venv. Если в пакете лежат sitecustomize.py,
  usercustomize.py или .venv, запуск откажется.
  Пакеты ставятся отдельно тем же Python, один раз, без повышения прав:
    py -3 -m pip install -r requirements-windows.txt

  В окне каждые 2 секунды одна строка. Кадр есть только если
  decoded_frames больше 0 и has_decoded_frame=True.
  Сервер принял событие только если event_http=200.
  heartbeat_http=200 — принят heartbeat.
  Слова opened в этой строке нет: открытый сокет кадром не считается.
  Остановить: Ctrl+C. После закрытия окна агент не работает и после
  перезагрузки сам не поднимется.

  Живой RTSP этим архивом не проверялся: компьютера салона в проверке не было.

Служба Install.bat — не проверка кадра и не объявлена безопасной
  Она просит администратора, ставит задачу Планировщика и закрывает
  каталоги. На компьютере салона она не запускалась. Для сдачи кадра
  её не используйте. Если её всё же запускают, Windows один раз покажет
  запрос UAC и создаст видимую задачу SentinelEdge: запуск при загрузке,
  без входа пользователя, от Local Service. Задача не скрыта. Повторный
  Install не ставит зависимости заново, если версии и исходники не менялись.
  4. Status.bat читает только %ProgramData%\SentinelEdge\status.json.
     Ключ и RTSP туда не пишутся. Строка opened без кадра успехом не является.
     Частота захвата берётся из SENTINEL_FPS_INFERENCE.
  5. Stop.bat создаёт %ProgramData%\SentinelEdge\control\stop.request.
     Этого достаточно обычному пользователю. Снять задачу в Планировщике
     может администратор. Uninstall.bat снимает задачу и не удаляет данные.
     Каталог ProgramData удаляет только администратор, отдельным действием.

Права
  Install.bat не скачивает Python. Нужен уже установленный
  %ProgramFiles%\Python312\python.exe. Загрузчика с python.org нет.
  Копия программы и окружение — %ProgramData%\SentinelEdge\app.
  Секреты — %ProgramData%\SentinelEdge\private. Обычные пользователи
  не читают private, app и models. Они читают status.json и logs и
  могут создать только stop.request. Задача Local Service запускает
  копию в ProgramData, а не папку, из которой нажали Install.bat.
  Антивирус и TLS не отключаются. Исключения не добавляются.
  Перед запуском Python установщик отказывается, если папка доступна
  на запись не администратору или сама является ссылкой. Каталог в
  ProgramData, который оказался junction, тоже не принимается.
  Если в ProgramData уже лежат config.env или yolo11n.pt и ими владеет
  не группа Administrators, Install останавливается. Файлы не удаляются
  и не читаются. Их нужно переложить вручную и запустить Install снова.
  Чужой python.exe в app\.venv владельцем не становится: каталог
  окружения удаляется до запуска и собирается заново из Program Files.

Ограничения, которые не обещаем
  Windows 7 и 32-bit не поддерживаются. Полная установка с UAC,
  перезагрузка, живой YOLO и живой RTSP этим архивом на салоне
  не проверялись.
  Ориентир по ресурсам, не замер салона: компьютер x64 с 4 ГБ ОЗУ и
  несколькими гигабайтами свободного диска под окружение CPU torch и
  модель yolo11n. Точный расход памяти на Windows здесь не измерялся.
  Доставка событий — at-least-once. Если процесс умер после ответа
  сервера 200 и до записи очереди, то же событие может уйти ещё раз.
  Сервер дубликаты не склеивает. При переполнении очереди (1000) самые
  старые события отбрасываются, счётчик dropped_oldest это показывает.
  Обрыв RTSP и обрыв API обрабатываются повторными попытками в том же
  процессе. Падение процесса поднимает Планировщик (перезапуск после
  ошибки, не чаще раза в минуту).

Журнал
  %ProgramData%\SentinelEdge\logs\edge.log, ротация 1 МБ, 5 файлов.
  Пароли и query-строки вырезаются. Diagnose пишет diagnose.json без
  кадров и без ключа API.
